# COMP 421 – Online Game Distribution Service Database

A multi-phase academic database project built for McGill's COMP 421 (Database Systems) course. The project models a Steam-like digital game distribution platform, covering everything from schema design to a working Java application backed by IBM DB2.

**Group 99:** Luca Mitran, Nicholas Imperioli, Ping-Chieh Tu

---

## Project Overview

The database tracks the full lifecycle of a game from its developer and publisher, through the store, to the end user including purchases, wishlists, discounts, friendships, and transaction history.

## Database Schema

The schema models a digital storefront with the following tables:

| Table | Description |
|---|---|
| `Developer` | Game studios that create games |
| `Publisher` | Companies that publish games |
| `Game` | Game catalog (name, price, rating, release date) |
| `Category` | Genre/tag labels (Action, Indie, RPG, etc.) |
| `BelongsTo` | Many-to-many: games ↔ categories |
| `MakePublish` | Ternary: game ↔ developer ↔ publisher |
| `Users` | Registered platform users |
| `BillingInfo` | Payment details per user (weak entity) |
| `Transactions` | Purchase records with status (Completed/Pending/Failed) |
| `Buy` | Ternary: user ↔ game ↔ transaction |
| `Own` | Games owned by a user |
| `Wish` | User wishlists |
| `InCart` | Games currently in a user's cart |
| `Discount` | Time-bounded discounts on games |
| `Friend` | User-to-user relationships with status (Pending/Accepted/Blocked/Rejected) |

### Key Constraints

- Game ratings are restricted to `[0.00, 5.00]`; prices must be `>= 0`
- Discount percentages are restricted to `(0, 100]`; end date must be `>= start date`
- Payment methods are limited to Credit Card, PayPal, Debit Card, or Gift Card
- Friend status is one of: Pending, Accepted, Blocked, Rejected
- A user cannot friend themselves (`uid1 != uid2`)

## Getting Started

### Prerequisites

- IBM DB2 client with access to the course server
- Java with the DB2 JDBC driver (`db2jcc.jar`) on your classpath
- Python 3 (only needed if re-scraping data from the Steam dataset)

### Setting Up the Database

From the `src/p2/` directory, run the convenience script to reset and reload the database:

```bash
./runall.sh
```

This runs in order: `droptbl.sh` → `createtbl.sh` → `loaddata.sh`, and writes execution logs to `Logs/`.

Alternatively, run each step manually:

```bash
./droptbl.sh      # Drop all tables (safe to run even if tables don't exist yet)
./createtbl.sh    # Create all tables with constraints
./loaddata.sh     # Insert 100 games, 10 users, and all related data
```

### Running the Java Application

Compile and run from `src/p3/`:

```bash
javac -cp .:db2jcc.jar GameDatabaseApp.java
java  -cp .:db2jcc.jar GameDatabaseApp
```

> **Note:** Update the `userid` and `password` fields in `GameDatabaseApp.java` before running, or set the `SOCSUSER` and `SOCSPASSWD` environment variables.

## Java Application Features

`GameDatabaseApp.java` is an interactive CLI application with eight options:

1. **Lookup Games by Category** — Lists all categories, then shows games matching your selection
2. **Add a New User** — Auto-increments UID and inserts a new user record
3. **Add Game to Wishlist** — Accepts a game name or ID; prevents duplicates
4. **View User Wishlist** — Shows wishlist with live discounted prices applied
5. **Apply Discount to Game** — Inserts a new discount, rejecting overlapping date ranges
6. **Buy a Game** — Handles the full purchase flow: creates a transaction, updates `Own`, removes from wishlist, and marks the transaction Completed (or Failed if already owned)
7. **Manage Friendship** — Add or remove friend relationships; enforces `uid1 < uid2` ordering to prevent duplicate pairs
8. **Show Purchase History** — Displays all transactions for a user with game names

## Data

Game data was sourced from the [Steam Games Dataset on Kaggle](https://www.kaggle.com/datasets/fronkongames/steam-games-dataset). The scraper (`src/p2/Scraped Data/loaddata.py`) processes `games.json` and outputs ready-to-run SQL INSERT files for the first 100 games with exactly one developer and one publisher.

The database ships with 10 sample users, billing info, transactions, friend relationships, wishlists, and purchase records.

## Notable SQL Features Used

- **Window functions** — `RANK() OVER (PARTITION BY ... ORDER BY ...)` for best-selling categories per year, friend game recommendations, and wishlist category rankings
- **CTEs** — `WITH` clauses for readable multi-step queries
- **`COALESCE`** — Graceful fallback when joins produce NULLs (e.g., users with no friends or empty wishlists)
- **Check constraints** — Inline validation on price, rating, discount range, payment method, and friend status
- **Views** — `BasicGameInfo` (budget games under $20) and `GamePurchaseDetails` (joined purchase summary)
